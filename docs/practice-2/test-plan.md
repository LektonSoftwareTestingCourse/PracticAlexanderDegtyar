# Тестовый план СМП

## 1. Области тестирования

- Authorization и Card Management - полная модель: классы эквивалентности, граничные значения, попарное тестирование, порядок проверок и причины отказа
- Остальные сервисы и инфраструктура - чек-листы дымового тестирования и критического пути

## 2. Критерии входа

- `docker compose up -d` поднимает 12 контейнеров без ошибок
- Все сервисы в состоянии `healthy`
- `./scripts/smoke-test.sh` завершается успешно
- Доступны требования: `tz/*` и api контракт `openapi.yaml`
- Сгенерировано не менее 100 тестовых карт

## 3. Критерии выхода

- Выполнено 100% запланированных тест-кейсов
- Нет дефектов критического или высокого уровня
- Дефекты Medium и Low зафиксированы
- Каждое требование ядра покрыто хотя бы одним кейсом
- Попарный набор покрывает 100% достижимых пар

## 4. Приостановка и возобновление

Приостановка:
- дымовой набор не проходит: стек не поднимается или сервис ядра недоступен
- доля падающих кейсов превышает 30% - дальнейший прогон не даст полезной информации

Возобновление:
- блокирующий дефект исправлен, дымовой набор проходит полностью
- тест-кейсы проходят успешно

## 5. Расписание

Проект конечный, поэтому план построен по водопадной схеме и синхронизирован с планом обучения: каждый этап тестирования привязан к модулю курса и выполняется последовательно.

- Практика 1. Запуск и дымовые проверки - поднятие стека, health-check всех сервисов
- Практика 2. Тест-дизайн ядра - классы эквивалентности, границы, попарный набор, чек-листы периферии
- Практика 3. Модульные тесты - бизнес-логика Authorization и Card Management в изоляции
- Практика 4. API и интеграционные тесты - контракты, работа с БД, взаимодействие сервисов
- Практика 5. E2E-сценарии - покупка, отказ и возврат целиком, баг-репорты
- Практика 6. Прогон в CI и нагрузочный smoke - автоматизация проверок, поведение под нагрузкой
- Практика 7. Сбор метрик и отчётность - покрытие, отчёты о прогонах
- Практика 8. Итоговая стратегия - coverage map, выводы о качестве, защита

## 6. Техники тест-дизайна

- Классы эквивалентности - статусы карт заданы фиксированным набором, каждый класс проверяется одним представителем
- Граничные значения - лимиты, баланс и срок действия проверяются тройками ON/OFF с шагом в одну копейку; для даты берутся предыдущий, текущий и следующий месяцы
- Попарное тестирование - сочетания статуса, сумм, срока действия, типа терминала и MCC; полный перебор избыточен
- Таблицы решений и диаграммы переходов состояний - применяются с модуля 3, в текущий артефакт не входят

## 7. Ресурсы и инструменты

Исполнитель: 1 студент-тестировщик. Отдельного стенда нет - проверки идут на локальном Docker и в CI-раннере.

*Языки: Java 21 для тестов бэкенда, TypeScript 5.7 для тестов дашборда.

Фреймворки и библиотеки:

- JUnit 5 и Mockito - модульные тесты
- REST-assured - API-тесты
- Testcontainers - PostgreSQL и RabbitMQ в контейнерах для интеграционных тестов
- WireMock и MockWebServer - заглушки внешних сервисов
- Awaitility - ожидание асинхронных событий из очереди
- Instancio - генерация тестовых данных
- TestNG - сквозные сценарии в модуле `e2e-tests`
- Vitest - тесты дашборда
- allpairspy - генерация попарного набора вместо PICT так, как тестирование производится на  macOS

Сборка и запуск: Maven, Docker Compose, GitHub Action.

## 8. Метрики покрытия

- Покрытие требований - требований с хотя бы одним тест-кейсом. цель 100%
- Покрытие пар - покрытых пар значений к достижимым. цель 100%
- Покрытие причин отказа - проверенных кодов ответа к описанным в ТЗ. цель 100%
- Доля пройденных кейсов - прошедших к выполненным. цель не ниже 95%
- Доля негативных кейсов - цель не ниже 50%

## 9. Риски
- Модель без ограничений - генератор включает невозможные сочетания, набор
  становится непригодным. Закрыто ограничениями C1–C4 в `pict/model.txt`;
  генератор проверяет выполнимость каждой строки
- Покрытие пар принимают за полноту - взаимодействия трёх и более параметров
  остаются непроверенными.
- pict не доступен на macOS - испольузется allpairspy
