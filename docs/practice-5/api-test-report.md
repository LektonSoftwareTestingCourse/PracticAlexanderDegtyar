## 4. Расхождения контракта и реализации

| Что обещает спецификация | Что следует из реализации | Классификация |
|---|---|---|
| Успешный ответ Gateway содержит MTI 0110 | `AuthorizationResponse.approved` сохраняет MTI запроса, обычно 0100 | Дефект контракта|
| Список мерчантов заявлен в OpenAPI | Gateway имеет шаблон `/api/simulator/merchant/**`, контроллер использует `/api/simulator/merchants` | Дефект маршрутизации|
| OpenAPI содержит terminal/start и terminal/status | Контроллер реализует POST start-continuous и POST stop | Устаревшая спецификация |
| В `docs/api/openapi.yaml` отсутствуют `POST /api/cards/bulk-update` и `POST /api/simulator/merchant/fee` | Оба эндпоинта реализованы в контроллерах и доступны через Gateway | Неполная спецификация |

## 5. Обоснование достаточности

По правилам валидации и коду сервисов определили, какие запросы должны проходить и какие ошибки могут возникнуть. Для ограничений длины полей и параметров пагинации проверили значения на границе и рядом с ней.

Для восьми фильтров поиска проверили все 28 пар. В каждом случае использовали отдельный номер карты (PAN) и проверяли два результата. Если оба фильтра подходят, запись находится. Если один из фильтров исключает запись, она не попадает в выдачу. При пагинации отдельно проверили, что общее число найденных записей сохраняется при смене страницы.

Для повторной доставки проверили создание новой записи, повтор того же запроса и конфликт при повторе с другой суммой. После конфликта проверили, что исходная запись сохранилась без изменений.

Данные для тестов создавали через HTTP.
